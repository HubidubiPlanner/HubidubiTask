How the whole system fits together

HubidubiOS Ecosystem

A personal task and notes system that runs on machines you own. A Linux workstation holds everything as plain files. A phone and a Mac each carry a full copy and keep working with no network. A Raspberry Pi gives a terminal at the desk, and a separate inference box answers the AI questions.

The machines and how they talk

Solid lines carry your data. Dashed lines are questions to a model or a one-way calendar pull. The Mac never talks to the workstation directly: the phone passes records and attachments between them on each round.

Where your data lives

Everything is a plain file in ~/vault on the workstation. The search index is rebuilt from the files at any time, so losing it loses nothing. The vault stays usable with an editor, grep and git even if every other part of HubidubiOS were deleted.

~/vault/ ├── inbox/ captures not yet sorted ├── current/ next actions, one file per project ├── waiting/ handed to someone else ├── maybe/ someday ├── archive/ done or dropped, still searchable ├── projects/ one file per project ├── notes/ text, photo, voice and file notes, the file beside its .md ├── calendars/ .ics events, Google's in calendars/google/ └── .hubidubios/ index, config.toml, sync and attachment store

The phone and the Mac each keep the same records in their own database. Attachments travel by their SHA-256 hash, so the same photo is stored once and every device can check it arrived intact.

The agent and plugins

The agent on the workstation lets the model plan one small step at a time while ordinary code does the work. Each turn the model picks one skill, its parameters are checked against that skill's schema, and the skill runs in a bubblewrap sandbox. The model never sees the whole vault: it asks a search skill for ranked snippets.

Plugins are ordinary Arch packages, so pacman handles versions and dependencies. Each plugin brings entity types and the skills the agent can call.
