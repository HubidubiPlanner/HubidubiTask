How it fits together

HubidubiTask Ecosystem

One app for tasks, notes and feeds, on Android, macOS and Linux. A phone and a computer pair once and keep each other current over your own Wi-Fi. Each has a full copy and works on its own. Four AI agents answer questions, review items and turn changed web pages into tasks.

Devices and connections

Solid lines carry your items: to the other device, and to the Harness with a review that may use tools. Dashed lines are questions to an AI or a feed's look at a page. There is no server of ours anywhere.

Harness computer

Any computer at home with Claude Code, Linux or macOS. It answers the apps' Harness questions; the apps only need its IP and port.

Source
src/harness/, one Python file, nothing to install
Install
sh deploy/harness/install.sh: a service on port 8765
Settings
~/.config/hubidubitask-harness: harness.env, mcp.json

Omarchy image

An Omarchy installer with the app installed. Nothing else of Omarchy changes, apart from boot fixes for new NVIDIA cards.

Build
deploy/omarchy/build-fork-in-colima.sh

AI

Settings offers four AI choices on every system: SelfHostedAI, the default, then OpenAI, Claude and Agent, which is the Harness. There is no chat: the AI reviews any item you long-press, and feeds use Claude or the Agent to write their task.

Harness requestClaude Code may useWorks in
ReviewsRead, Glob, Grep, WebFetch, subagents, your items as MCP tools (search, upcoming, projects, project, inbox, add_task, capture, mark_done), and the MCP servers in that computer's mcp.jsonA fresh Markdown copy of the items the app sent
FeedsNothing: text only, because a page's text comes from strangersAn empty folder

Always in Claude Code's restricted mode, with only the listed MCP servers and every permission prompt answered no: nothing runs commands or edits files. The item tools change nothing on the Harness computer; the app applies the changes to its own items. A harness.env next to the Harness's settings can point Claude Code at a local model instead of its own login.
